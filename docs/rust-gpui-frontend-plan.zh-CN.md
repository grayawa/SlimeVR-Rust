# GPUI Kit 原生前端迁移计划（草案）

日期：2026-10-05。当前阶段：已开始原生原型，完整迁移仍按下列阶段推进。代码与运行说明见 [gui-gpui](../gui-gpui/README.zh-CN.md)。

## 目标与技术选择

使用用户指定的 [GPUI Kit](https://gpui-kit.com/)（[longbridge/gpui-kit](https://github.com/longbridge/gpui-kit)），把 React / WebView 界面逐步迁移到 Rust 原生界面。目标是降低前端内存。界面沿用现有侧边栏、设置分组、功能内容和操作步骤；已确认的交互调整为修正“工具 → VRChat 设置警告”的导航返回行为。

官网当前版本为 0.7.1。实施时锁定经验证的 GPUI Kit 版本及其匹配的 GPUI 依赖，避免单独升级底层快照。初期使用 `gpui-component` 的现成组件，按需调整 SlimeVR 主题；自定义交互可使用 `gpui-base`。依赖和功能选项按实际需求选择。

原生界面直接绘制，不嵌入现有网页。现有 Rust 服务端继续负责接收、算法、校准、SteamVR、配置保存和导出。Tauri 版保留作为迁移期间的可用版本和对照。

“Rust 原生”本身不能保证更低内存。字体、GPU 资源、3D 模型、消息队列和缓存仍可能占用大量资源，需要等价场景实测。

## 可复用的内容与需要重做的内容

| 内容 | 迁移方式 |
| --- | --- |
| Rust 后端、算法与 SteamVR 桥 | 继续使用现有服务端进程 |
| SolarXR / FlatBuffers 协议 | 使用仓库现有 Rust 生成绑定，实现独立轻量客户端 |
| `vrconfig.yml` / `.yaml` | 仍由后端读取和保存，界面通过现有 API 修改 |
| Fluent `.ftl` 与消息 ID | 用 Rust Fluent 实现应用文案，保留语言回退和 `override.ftl` |
| GPUI 组件内部文案 | 与应用语言同步；组件内置本地化与应用 Fluent 分开接入 |
| 日志分级和文件轮转 | 复用与 Tauri 无关的日志逻辑，接入新宿主 |
| 后端启动、退出、单实例、托盘、目录和文件选择 | 提取可独立使用的逻辑，并替换 Tauri API 调用 |
| React 页面、hooks、CSS 和路由 | 用 GPUI 状态、视图和导航重新实现 |
| Three.js 骨架 / 模型预览 | 独立验证 Rust 渲染和 GPUI 集成方案 |
| 音效 | 复用声音素材，重新实现播放与事件去重 |
| GUI 偏好 | 兼容现有数据目录，规划已有偏好的导入及新字段；保存方案待界面需求确定 |

不增加另一份后端 JSON 配置。GPUI Kit 有自己的组件本地化机制，但迁移应用文案时没有必要把现有 Fluent 翻译改成另一套格式。

## 初期结构

```text
GPUI 原生桌面程序
├── 页面与表单：展示数据、收集用户操作
├── 应用状态：设备快照、连接状态、未完成操作、导航
├── SolarXR 客户端：WebSocket、事务号、订阅、重连
├── 原生宿主：后端生命周期、托盘、日志、文件和音频
└── 本地化与资源：Fluent、字体、图片、声音
                 │
                 │ 现有 SolarXR / WebSocket
                 ▼
          现有 Rust 后端进程
```

新 GUI 可放在独立的 `gui-gpui/` 目录，开始时不依赖整个服务端 crate，避免把固件刷写、设备接收等依赖带入界面程序。通信层依赖现有协议绑定即可。

当前原型已采用该目录与依赖结构；GPUI Kit 及底层匹配版本通过独立 `Cargo.lock` 锁定。

网络和阻塞操作在后台执行，UI 线程负责状态应用与绘制。设备数据读取频率、姿态显示频率与服务端解算频率分别控制；现有服务端 4 ms 解算周期不因换界面而改变。

消息处理约束：

- 姿态与遥测保留最新快照，使用有界队列，避免处理积压的旧帧。
- RPC 结果、错误、敲击通知和重置进度按事件处理，不能套用丢弃旧快照的策略。
- 重连恢复读取请求和订阅；重置、录制等操作不自动重发。
- 服务端设置回包只更新状态；表单写入由明确的用户操作触发。
- 分配页的敲击模式由页面与连接生命周期控制，保留 fix4 已验证的有限切换行为。
- 音效按操作、阶段和进度去重，避免回包或重连导致重复播放。
- 页面离开时释放订阅和任务；界面隐藏时降低可视化更新开销。

## 分阶段实施

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| 0：功能清单与性能基线 | 按已确认的界面范围列功能清单；测量 Tauri、Electron 在等价场景的资源占用 | 明确迁移顺序、对照场景和可量化验收目标 |
| 1：Windows 与通信原型 | 原生窗口、中文字体与输入、主题、连接状态、设备列表、读取设置 | Windows 实机能接收真实设备数据，中文和 DPI 正常，连接恢复可靠 |
| 2：最小可用操作闭环 | 设备批准与分配、重命名、完整 / 朝向 / 安装方向重置、暂停、基础比例、音效、日志入口、现有侧栏与设置导航、VRChat 警告返回 | 现有设备能完成日常初始化；配置仍通过现有 API 保存；无设置回写循环；已迁移页面沿用原有入口；警告页可回到原设置页 |
| 3：可视化验证 | 简单骨架先验证数据与绘制；再决定完整 3D 模型和交互方案 | 实机显示正确，窗口切换和隐藏能释放或暂停资源，记录内存与 GPU 开销 |
| 4：完整功能迁移 | AutoBone、StayAligned、校准向导、设备高级设置、OSC / VMC、串口 / Wi-Fi / 固件、BVH、SteamVR 检查、VRChat 提示 | 对照当前界面功能清单逐项完成，所有延后项目有明确记录 |
| 5：发行与替换 | 单实例、托盘、偏好导入、多语言覆盖、快捷操作、更新入口、解压包和统一测试 | 可供普通用户解压运行；功能与性能验收完成后再决定默认界面 |

现有 3D 模型和骨架预览按保留功能规划，第一阶段提前验证其渲染集成可行性，第三阶段完成可视化迁移，避免大量页面完成后才发现集成受限。

首次设置、分配、佩戴校准和身体比例的入口与具体操作步骤继续沿用。VRChat 警告的导航返回行为按下述要求实现。

## 已确认的导航范围：沿用原有侧边栏

主侧栏保留现有入口、名称与顺序：主界面、追踪器分配、佩戴校准、身体比例、连接追踪器，以及底部的设置入口。主页继续作为默认打开的页面，保留设备状态、预览、重置和暂停等常用操作。

设置区域沿用现有分组与入口，主题、语言、引导、追踪参数、SteamVR、OSC / VMC 和工具保持原有归属。

此前讨论的常用设置提升到主侧栏、设备入口收拢、输出与连接入口及“软件设置”拆分均已取消，不作为实施要求。

验收：完整迁移后，原有页面均可通过熟悉的入口访问，主侧栏与设置分组没有重排。导航本身不触发额外的配置写入。

## 已确认的交互调整：VRChat 设置警告

现有“设置 → 工具 → VRChat 设置警告”链接跳转到独立的 `/vrc-warnings`。该路由使用 `MainLayout`，位于 `SettingsLayout` 外，因此设置侧栏消失；主导航的“设置”入口固定指向 `/settings/trackers`，不能回到先前选中的设置页。这与用户反馈吻合。

新前端的行为要求：

- VRChat 设置警告仍从“设置 → 工具”进入，作为设置区域内的工具子页展示，保留主侧栏与设置导航。
- 打开前记录原功能页或设置页、原选中小节和滚动位置；存在未提交的本地编辑时，返回后保留编辑内容。
- 提供明确的“返回”操作，恢复打开前的位置，不固定回到某个默认设置页。
- 用户仍可直接通过导航切到其他页面；多次打开警告页时更新返回来源，避免回到过时的页面。
- 从追踪检查清单等其他入口打开警告时，返回原入口。没有有效来源时提供明确的设置首页入口。
- 警告内容、静音选项和检查逻辑维持现有行为；返回行为不触发配置保存、重置或其他业务操作。

导航状态使用轻量记录；不为恢复位置而永久保留全部页面及其 3D/GPU 资源。

验收例子：在串口设置或 OSC 设置中选中某一小节，打开 VRChat 设置警告，再点击返回，应恢复同一设置页、选中小节和滚动位置。重复打开、从检查清单进入及首次直接打开也应有可预测的返回路径。

## 性能与回归验收

使用 release 构建，对齐后端、设备数量、订阅频率、窗口大小、预览开关和日志级别。

前端内存统计应覆盖该应用的进程树，包括属于它的 WebView2 子进程；后端单独记录。主要比较私有内存，同时记录工作集、CPU 和 GPU 内存。不要直接把含共享页的工作集相加当作总实际内存，也不要把新 GUI 的空窗口与旧 GUI 的完整 3D 页面比较。

建议场景：启动空闲、六设备常用页面、分配页反复进出、预览开关、窗口最小化、断线重连，以及连续使用 30–60 分钟。以取得的基线确定内存下降目标；原型的结果只代表已实现且等价的功能范围。

必须保留此前修复的验收项：

- 分配页无持续设置请求，不因设置回包引发断联。
- 后端重启后恢复连接和订阅，未完成操作有清楚反馈。
- 重置结果与进度一致，音效没有重复触发。
- 使用原有 YAML 配置，更新后设备分配与校准状态正确。
- SteamVR 驱动的已有安装仍作为信息提示处理。
- BVH 录制停止与程序退出正常完成文件保存。
- 日志级别、来源与轮转在 Windows 正常工作。
- VRChat 设置警告保持导航，返回恢复原页面与位置，不遗失未提交的本地编辑。
- 主侧栏入口、顺序和设置分组沿用现有版本，原有设备操作与设置均可完整访问。

## Windows 与发行约束

用户目标仍优先 Windows 11 x64，Windows 10 列入兼容验证。GPUI Kit 官方文档要求 Windows 10 或以上，并要求使用 MSVC Rust 工具链、Visual Studio C++ 构建工具和 Windows SDK；不能直接照搬目前 Windows GNU 交叉编译流程。开发工具要求与最终用户运行要求分开处理。

采用 Windows MSVC 的构建与测试任务，验证普通窗口、中文输入法、多屏与 DPI、托盘和真实显卡上的绘制。自动测试及编译通过不能替代原生窗口与显卡实测。

完整原生 UI 路线无需通过 WebView2 显示页面。发行时核对所选依赖和运行库，再提供解压包。初期不承诺单 EXE，也不因用户无需安装 Rust而忽略运行库检查。

## 已确定范围与待技术验证项

已确定：保留现有前端功能、侧边栏、设置分组和具体操作步骤，主页仍为默认页面；修正上述 VRChat 警告导航。分阶段交付不表示删除后续阶段的功能；迁移期间保留 Tauri 版和现有网页入口。

待验证：Windows MSVC 构建与中文输入、3D 集成、等价场景的内存收益、Fluent 文案渲染，以及已有 GUI 偏好的导入方式。

当前建议的第一交付物仍是“原生设备主页、分配与重置”的可用闭环，并同时验证 Windows 与渲染基础。设置导航的返回要求纳入应用导航设计，完整功能按清单逐项迁移。

## 当前原型进度（2026-10-05）

已实现设备主页、原版侧栏入口、设备状态与身体分配、三种重置、暂停、SolarXR 自动重连和只读设置摘要。已有原生二维骨架预览；完整 3D 集成仍待验证。VRChat 警告页保留设置导航、返回来源和页面滚动状态，读取现有检查结果并支持消除警告。中英文复用现有 Fluent 文件。

状态与通信测试、六台模拟 UDP 追踪器的真实 Rust 后端联调、YAML 分配保存、重置与暂停已通过。Linux 原生构建与实际窗口绘制已验证，并进行了页面导航检查。Windows MSVC 工作流已添加但尚未执行，Windows 实机测试与性能基线仍未完成。

阶段 1 / 2 已开始，尚未达到完整完成标准：设备批准、重命名、比例表单、音效、完整设置、正式文件日志与原生宿主集成仍需迁移。原型运行范围及延后功能以 [README](../gui-gpui/README.zh-CN.md) 为准。
