# GPUI 功能对照与统一测试

GPUI 的主要操作流程以 React / Tauri 界面为参照，代码位于独立的 `gui-gpui/`。界面使用 GPUI Kit 并调用 Rust 后端。主侧栏和默认主页保留；VRChat 警告可返回来源设置页，并保留编辑与滚动位置。

本轮视觉调整和验证边界见 [界面对齐说明](rust-gpui-ui-alignment.zh-CN.md)。

## 功能对照

| 范围         | 原生实现                                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------------------- |
| 连接         | SolarXR WebSocket，心跳、超时、重连、有限命令队列，重连恢复读取与订阅                                     |
| 实时数据     | 遥测 100 ms、骨架 25 ms；可选 11 ms；隐藏窗口降频，离开预览停骨架订阅                                     |
| 设备         | 批准未知设备、分配模式、全部取消分配、敲击高亮、详情、命名、安装方向、磁力计、遗忘与重新允许连接          |
| 重置         | 完整、航向、安装方向、脚部与手指分组；暂停 / 恢复；按会话、事务、阶段和秒数去重音效                       |
| 比例         | 21 个骨架参数、分组长度及比例、按 HMD 身高重建、导入 / 导出、恢复默认                                     |
| 校准         | AutoBone 录制、停止、取消、处理、保存、结果和应用；身高记录 / 取消；Stay Aligned 放松姿势记录 / 清除      |
| 后端设置     | SteamVR、过滤、漂移补偿、重置、HID、FK / 约束 / 腿部修正、手势、Stay Aligned、AutoBone                    |
| OSC / VMC    | OSC 路由、VRChat 跟踪输出、OSCQuery、VMC 参数、VRM / glTF JSON 提取和清除                                 |
| 工具         | 串口枚举 / 开关 / 命令 / 日志、Wi-Fi、OTA、固件构建服务、串口刷写、快捷键及诊断                           |
| 固件         | 官方分批发布规则、电量限制、SHA-256、自定义 URL / 偏移、构建状态 / 错误、队列停止                         |
| 检查清单     | 状态、描述、忽略 / 恢复、导航到对应配置、启动 SteamVR / 打开网络设置 / 启用驱动 / 关闭手部输出            |
| VRChat       | 当前 / 建议配置、静音警告、返回实际来源设置页                                                             |
| 预览与输出   | 三维骨架、原 tracker / extension 模型、镜像、视角、鼠标旋转 / 移动 / 滚轮缩放、临时腿部修正、BVH          |
| VR 控制      | 重置、暂停、BVH、Overlay RPC 与原 Pub/Sub `display_settings` 主题                                         |
| GUI 偏好     | 原偏好读取与保存、主题、语言、嵌入字体、字号、网格 / 表格、预览、开发显示、声音、托盘、退出提示、Discord  |
| 桌面生命周期 | 本机单实例唤起、后端日志合并、轮转、panic 日志、Windows 启动失败对话框、优雅退出、原生文件 / 目录和剪贴板 |
| 引导         | VR / 动捕、连接 / 配网、分配、安装校准、比例、持续对齐、检查清单与完成状态                                |

设置草稿收到回包时保留未保存修改；只保存受影响的设置组，核对回包后解除保存等待。失败 / 超时保留草稿。分配敲击模式只在页面或会话状态变化时写一次，设置回包用于更新读取状态。

协议适配覆盖现有 86 种 RPC 和 Pub/Sub，使用上游 FlatBuffers 构造器与验证器；内部 JSON 表示表单状态。BVH 文件使用字节 payload，VRM 状态共享存储，实时帧通过最新快照传递。

## 验证

- 自动检查覆盖：86 种 RPC 编解码、错误输入、两路订阅、重连恢复读取、导航、草稿确认、音效去重、已有偏好保留、单实例、比例、固件表单、Overlay、GLB、29 种语言、日志、Discord IPC，以及着色器源码和 include 的完整嵌入。另覆盖原版检查清单排序、跳过、阻塞、进度与可见性，设置布局的协议字段与枚举值，以及 GUI 重置保留语言和未知字段。
- 真实 Rust 后端联调通过：6 台模拟 UDP 设备、分配和 YAML 保存、3 种重置、暂停、设置回读、比例导入、BVH 文件、AutoBone 录制与完成事件；使用模拟 HMD 位置。
- Linux 原生窗口操作验证：设置表单、分配 / 安装 / 比例 / 连接页面、反复进入分配页无断联；VMC 编辑经过 VRChat 警告后保留，返回及保存写入 YAML。
- Linux 与 Windows 全目标 `clippy -D warnings` 通过；Windows x64 优化构建、PE / DLL 依赖和压缩包完整性检查通过。
- Windows 着色器测试程序在 Wine 10 + Microsoft D3DCompiler_47 下运行通过：从空工作目录编译全部 18 个入口并验证 DXBC，验证范围为该兼容环境中的 shader 编译。

Windows 11、真实追踪器、SteamVR / VRChat、串口刷写和音频设备分别按实机步骤验收。内存比较使用等价功能、预览与设备条件。

Windows renderer 将 HLSL 和 include 嵌入程序，通过 D3DCompiler_47 在内存编译。Release 使用优化 shader，图形调试断言保持关闭。Windows 构建检查全部 18 个 shader 入口，打包核对加载方式。启动 panic 写入日志并显示错误对话框。

## 实现边界

骨架和追踪器用 GPUI 原生绘图展示真实三维数据，材质及引导布局与网页不同。新增文案提供中文 / 英文，其余语言复用原翻译并回退英文；系统对话框取决于操作系统语言。固件构建需要已有固件服务，其地址可配置。Discord 需要本机客户端。

诊断使用本地日志。SteamVR 驱动、仪表盘与第三方资源由对应组件管理。设置控件按现有前端与后端共同实现的操作生成。

## 一次性实机测试

1. 退出旧前端和原版 Java 后端，解压整个目录，双击 `SlimeVR.exe`，界面使用原生渲染器。保持原有 SteamVR 驱动。确认已读取自己的 YAML、偏好和语言。
2. 开机连接追踪器，检查分配、名称、电量和姿态；做完整 / 安装方向重置，抬腿和转身检查 SteamVR / VRChat。确保左右设备佩戴正确。
3. 反复切换分配页和设置页；VMC 页编辑一个值，进入 VRChat 设置警告，再返回，检查草稿和滚动位置。
4. 按需检查 AutoBone / 身高校准 / Stay Aligned、比例导入导出、BVH 文件和退出保存、OSC / VMC 与 VRM、快捷键、串口 / 配网及固件。
5. 检查完整音效顺序和单次播放、语言 / 主题 / 字体 / 布局、托盘隐藏恢复和重复启动只唤起窗口。
6. 比较相同追踪器、同样预览状态下的 CPU 与内存。如果异常，退出后用 `Start-SlimeVR-Debug.cmd` 复现，并压缩 `%APPDATA%\dev.slimevr.SlimeVR\logs`；正常启动恢复 info 级别。

包内也保留已有后端统一验收清单。真实刷写请选择实际匹配的板型和固件，执行前界面会要求确认。
