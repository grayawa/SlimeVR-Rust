# SteamVR 手部追踪 / 手柄切换修复

2026-10-06，Windows 包标识 `GPUI-test6-handfix1` / `Tauri-fix6-hand1`。GPUI 保留 test6-pages1 的界面；Tauri 使用既有 React 界面，此修复位于两个版本共用的 Rust 后端 SteamVR 输入会话。

## 原因与处理

SteamVR 可用不同设备 ID 表示同一只手的手部追踪和手柄。原实现只记录某个身体部位是否已经发布姿态：新设备接管后，旧设备迟到的断开、超时、重新注册或无定位消息仍可能清掉该部位。后端随之从 SolarXR 设备列表移除手部节点，因此两个前端都可能受到影响。

现在按身体部位记录最后发布有效姿态的设备 ID。清理消息仅能清掉该设备仍然负责的节点；旧设备的失效消息不能删除新设备的姿态。失效设备的姿态缓存仍会清除；当前设备真正断开或超时时仍停止使用其姿态，恢复状态与有效数据后可以重新出现。

这个路径已用模拟输入复现：旧版中，设备 3 接管左手后，设备 1 的断开通知导致左手节点消失。修复版保留设备 3 的姿态和 SolarXR 列表中的左右手节点。用户具体的切换入口和头显型号尚未确认，实机是否存在其他路径仍需验证。

## 验证与实机步骤

SteamVR 与外部输入的 15 项相关测试通过。新增回归包含两种角色切换方向，分别覆盖旧设备的断开、超时、重新注册和无定位消息，并检查生成的 SolarXR 设备列表；也检查当前设备断开后清理与恢复数据后重新接入。Linux 与 Windows GNU 目标的 Clippy（`-D warnings`）通过。Windows GNU 发布构建与打包校验用于交付；Windows 实机手部切换尚未验证。

测试此包前先完全退出旧 SlimeVR 前端和后端，再启动新包。若旧后端仍占用服务端口，前端会连接旧后端，修复不会生效。已有 SlimeVR SteamVR 驱动可继续使用。

1. 让左右手柄正常连接，确认 SlimeVR 主页左右手节点可见。
2. 在头显 / SteamVR 中切到手部追踪，再切回手柄，重复数次；检查节点是否恢复及姿态是否继续更新。
3. 真正关闭一个手柄时，检查它的旧姿态不会持续作为有效输入；重新打开后检查恢复。
4. 若仍消失，完全退出后用 `Start-SlimeVR-Debug.cmd` 启动并复现，保留 `%APPDATA%\dev.slimevr.SlimeVR\logs\gui-gpui.log`，记录头显型号、切换入口和消失的是 SlimeVR 还是 SteamVR 列表。

同时清理了 Windows 条件编译代码和测试辅助项的 Clippy 警告，不改变 VRChat 注册表读取逻辑。

后端继续使用既有 `vrconfig.yml` / `.yaml`，本包不包含个人配置或日志。驱动、Bindings Provider 和依赖沿用 fix5；包内 `slimevr-server.exe` 更新为此修复。
