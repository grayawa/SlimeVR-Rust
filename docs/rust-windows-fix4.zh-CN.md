# Windows 修复包 fix4

包含此前连接、重置音效和已有 SteamVR 驱动提示的修复，继续使用现有配置和系统 WebView2。

## 追踪器分配页面的设置回写循环

分配页原先监听完整的 `SettingsResponse`，将收到的敲击设置保存在 React 状态中，并在该对象改变时关闭、重新开启敲击分配模式。Rust 后端会在设置修改后广播最新设置，这又触发页面回写，形成循环。

实际 Chromium 浏览器中，旧版页面停留 10 秒发送约 3,100 个请求。新增生产网页回归测试也在旧版上失败：8 秒内出现 1,797 次敲击设置修改。这会持续写配置、增加 CPU 开销及连接消息积压。本地测试未复现设备环境中的连续断联；用户安装 fix4 后已反馈分配页连接稳定。

现在分配模式只随页面挂载、卸载和连接恢复进行切换，不再依赖设置响应。请求仅包含 `setupMode`，不会将过时的敲击次数、延迟或重置开关写回。连接已经断开时，页面清理请求直接跳过，不再弹出额外的“操作未完成”。

导航布局切换可能短暂重新挂载页面，产生有限的开关请求；页面稳定后不会继续发送设置修改。

## 验证

新增测试运行实际生产网页及真实 Rust 后端，检查页面停留时连接和数据流持续正常、其他设置更新不触发回写、离开页面关闭模式、再次进入开启模式、主动断线后恢复订阅和分配模式。最终设置检查确认原有敲击参数不变。

浏览器测试、24 个 GUI / 桌面 / 后端协议测试、TypeScript 和改动文件 ESLint 检查通过。Windows GUI 使用 release 交叉编译；后端沿用 fix3，腿部算法不变。包内文件哈希与 ZIP 完整性已检查。本环境未执行 Windows 原生运行。

## 实机复测

退出旧版后完整解压并运行 `SlimeVR.exe`。进入“追踪器分配”停留一分钟，再来回切换几次，确认连接稳定、设备状态仍更新。若仍然断联，请提供发生时间及压缩后的 `gui-tauri.log`。
